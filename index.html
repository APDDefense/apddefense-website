Three technologies, each with its real status.

TECH 01 Verified on hardware

Secure Hardware-Accelerated Link

AES-256-CCM authenticated encryption

Traffic on the radio link is protected with authenticated encryption, run on the radio processor's hardware cryptography engine.

Demonstrated

  • Authenticated encryption, with the packet header bound in as authenticated associated data.
  • Nonce uniqueness maintained across reboots and across firmware reflash.
  • Sliding replay window that tolerates reordered packets while rejecting replays.
  • Tampered and replayed packets rejected — proven by fault-injection testing on the hardware.

Not claimed

  • No independent security evaluation or cryptographic certification has been performed, and none is claimed.
TECH 02 Partial · in development

Sub-1 GHz Tactical Mesh

Relay verified between two nodes only

A sub-1 GHz mesh intended to stay resilient in austere, infrastructure-free environments. The relay foundation is working; the mesh itself is not yet proven.

Demonstrated

  • Bidirectional nodes with beacon-based neighbor discovery.
  • Flood relay with duplicate suppression, verified on two nodes.

Not yet

  • Multi-hop operation across three or more nodes is unverified.
  • Routing and delay-tolerant store-and-forward are in development.
  • LPD / FHSS / anti-jam waveforms are not built — see Roadmap below.
TECH 03 Partial · no sensors yet

Soldier Health & Casualty Telemetry

PulseLink, by APD Defense

PulseLink is an Android triage app for medics, fed by a compact health-telemetry format carried over the encrypted radio link.

Built

  • Telemetry wire format and its encrypted radio path.
  • The PulseLink Android application.
  • With no sensor present, the system reports “no reading” by design — it never estimates or simulates a vital sign.

Not yet

  • The current hardware carries no physiological sensors. Real-time vitals depend on sensor integration, which is roadmap.
  • The direct phone-to-radio connection has not yet been verified on hardware.

02  /  Integration & roadmap

Demonstrated with ATAK. The rest is labeled roadmap.

Demonstrated

ATAK / Cursor-on-Target

Demonstrated

  • Cursor-on-Target events fragmented, carried over the encrypted radio link, reassembled and displayed in ATAK-CIV.
  • Full duplex, with live GPS positions originating from the handsets.
  • Performed through a PC-hosted bridge between handset and radio.

Not yet

  • A direct Android-to-radio connection, without the PC bridge.
  • PulseLink casualty / MEDEVAC events have not yet been ingested by a TAK client.
Roadmap · not built

LPD / FHSS / Anti-Jam

Frequency hopping for low probability of detection and jamming resistance is a planned phase of the radio. None of it exists today: the current link operates on a fixed channel. It will follow multi-node mesh verification and the applicable regulatory review.

Roadmap · not built

Voice & Body-Worn Sensing

Low-bit-rate voice (Codec2), encoded on the handset and relayed by the radio as data frames, is planned and not built. Body-worn physiological and motion sensor integration is likewise planned; sensor hardware has not been selected.

Roadmap items describe intent, not commitments, schedules or performance guarantees.

SBIR phase alignment

Structured around the SBIR phase model

Our development plan is organized the way the DoD SBIR/STTR program is: feasibility first, then prototype, then transition. No SBIR award has been made to APD Defense to date; this describes how the work maps to the program’s phases.

FEASIBILITY
Encrypted link and CoT relay demonstrated on development hardware.
PROTOTYPE
Multi-node mesh, sensor integration, direct handset link — in development.
TRANSITION
LPD / FHSS waveforms, voice, production hardware — roadmap.
